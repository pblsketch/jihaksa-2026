Apps Script 판을 **Supabase(백엔드) + GitHub Pages(배포)** 로 다시 만든 것입니다.
활동 내용·문항·디자인은 원본 그대로 두고, 실시간과 진행 제어만 새로 만들었습니다.

- 참가자 화면 · `index.html`
- 실시간 현황판 (모니터 투사용) · `board.html`

## 1. 왜 다시 만들었나

Apps Script에서 실시간이 안 됐던 건 설정 문제가 아니라 구조 문제였습니다.

| | Apps Script | 지금 |
|---|---|---|
| 갱신 방식 | 5초 폴링 | 웹소켓 푸시 (Supabase Realtime) |
| 실제 지연 | 최악 10초 (폴링 5초 + 캐시 5초) | 0.1~0.3초 |
| 동시 실행 | 상한 30 — 50명이면 폴링만으로 잠식 | 해당 없음 |
| 과제 열기·닫기 | 없음 (항상 열림) | 과제별 토글, 켜는 즉시 참가자 화면이 바뀜 |
| 관리자 실습 확인 | 사람별 표를 세로로 나열 (50명이면 수십 화면) | 과제 성격별 전용 현황판 4종 |

## 2. 설치 — 딱 한 번만 하면 됩니다

### ① Supabase 스키마 적용

1. https://supabase.com/dashboard/project/wzvcienycrebfpqjpwzv 접속
2. 왼쪽 메뉴 **SQL Editor** → **New query**
3. `supabase/schema.sql` 파일 내용을 **통째로** 붙여넣고 **Run**
4. `Success. No rows returned` 가 나오면 끝입니다

> ⚠ 이 SQL은 다시 실행하면 **응답이 모두 지워집니다.** 연수 당일에는 절대 다시 실행하지 마세요.
> 리허설 기록만 지우려면 관리자 화면의 「응답 모두 비우기」를 쓰세요.

### ② Realtime 확인

스키마 SQL이 Realtime 설정까지 함께 켭니다. 확인하려면
**Database → Replication → `supabase_realtime`** 에 아래 5개가 들어 있으면 됩니다.

`participants` · `ox_responses` · `practice_responses` · `sentences` · `settings`

### ③ 배포

이 폴더를 GitHub 저장소에 올리고 **Settings → Pages → Source: `main` / `root`** 로 켜면 끝입니다.
빌드 과정이 없는 순수 정적 파일이라 그대로 올라갑니다.

## 3. 연수 당일 운영

### 관리자로 들어가기

참가자 화면에서 연수(8월 22일)를 고르고, 이름 칸에 **`박준일0822`** 를 입력하면 관리자 화면으로 들어갑니다.

### 진행 순서

1. 관리자 화면 **진행 제어** 탭 — 처음에는 4개 과제가 **모두 닫혀** 있습니다
2. 모니터에 띄울 화면은 **현황판** 탭에서 새 탭으로 엽니다 (F11 전체화면 권장)
3. 활동을 시작할 때 해당 과제 토글을 켭니다
   → 선생님들 화면이 **저절로** 바뀝니다. "새로고침하세요" 안내가 필요 없습니다
4. 활동이 끝나면 토글을 다시 꺼도 되고, 켜 둔 채로 다음으로 넘어가도 됩니다

| 토글 | 하는 일 |
|---|---|
| ① O·X 퀴즈 | 퀴즈를 열고 닫습니다 |
| ② 실습 A · 나의 미래 일기 | 실습 A를 열고 닫습니다 |
| ③ 실습 B · 학술 연구 포스터 | 실습 B를 열고 닫습니다 |
| ④ 오늘의 한 문장 | 문장 활동을 열고 닫습니다 |
| OX 정답 공개 | 켜면 참가자 화면·현황판에 **정답과 방송 패널 성적표**가 동시에 뜹니다 |
| 자료 전체 공개 | 켜면 과제를 다 안 해도 자료가 열립니다 (강제 공개) |
| 실습 A·B 둘 다 필수 | **기본 꺼짐** — A 또는 B 하나만 내도 자료가 열립니다 |

### 현황판 4종 (모니터용)

`← →` 키로 화면을 넘기고 `F` 로 전체화면이 됩니다.

| 화면 | 무엇을 보여주나 | 이야기 소재 |
|---|---|---|
| ① O·X 퀴즈 | 문항별 O/X 큰 막대 + 실시간 인원. 정답을 켜면 정답 테두리와 패널 성적표가 붙습니다 | "가장 문학적인 문장에 사람이 몰렸는데, 그게 AI였습니다" |
| ② 실습 A | 활동 9개 × 허용 단계 5개 **히트맵**. 색이 진할수록 그 단계에 몰린 것. 오른쪽은 외주화 위험 상·중·하 분포 | **「판단 갈림」 배지**가 붙은 활동 — 과반이 없는 곳이 토론거리입니다 |
| ③ 실습 B | 활동 7개로 동일 | 위와 같음 |
| ④ 한 문장 | 문장 카드가 3열로 쌓이고, **새 문장은 노란 테두리로 떨어집니다** | 마지막 장면용 |
| 제출 현황 | 과제별 제출 게이지 4개 + 참가자 이름 칩 (점 4개 = OX·A·B·문장) | 다음 활동으로 넘어갈 타이밍 판단 |

### 자료 공개

- 자동 — **OX + 실습(A 또는 B) + 문장**을 모두 낸 분에게 자료 메뉴가 열립니다
- 수동 — 「자료 전체 공개」를 켜면 누구에게나 열립니다 (마무리 때 켜시면 됩니다)

## 4. 알아 두시면 좋은 것

- **입력 중이던 실습 내용은 기기에 자동 저장됩니다.** 과제가 닫혔다 열려도, 화면을 껐다 켜도 남아 있습니다.
- **다시 제출할 수 있습니다.** 같은 과제를 다시 내면 이전 것을 덮어씁니다 (사람별 1건).
- **이름으로 이어하기** — 중간에 나갔다 같은 이름으로 들어오면 이어집니다. 동명이인은 「새로 시작」을 고르면 별개로 잡힙니다.
- **OX 정답은 서버에만 있습니다.** 「정답 공개」를 켜기 전에는 브라우저 개발자 도구를 열어도 안 보입니다.
- **쓰기는 전부 서버 함수(RPC)를 통과합니다.** 프론트에 있는 publishable key로는 남의 응답을 고치거나 지울 수 없습니다.
- **닫힌 과제는 서버가 거부합니다.** URL을 직접 쳐서 들어가도 제출이 안 됩니다.

## 5. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 화면이 「불러오지 못했습니다」 | 스키마 SQL을 실행했는지 (2-①) |
| 토글을 켜도 참가자 화면이 안 바뀜 | Realtime에 `settings` 가 들어 있는지 (2-②). 20초마다 자동 재조회하는 안전망이 있어 늦어도 20초 안에는 반영됩니다 |
| 관리자 토글이 "관리자 인증에 실패했습니다" | 브라우저를 새로 열고 `박준일0822` 로 다시 들어가기 |
| 현황판 오른쪽 위가 「연결 중…」에서 안 바뀜 | 웹소켓이 막힌 망입니다. 20초 폴링으로 계속 동작하니 그대로 쓰셔도 됩니다 |

## 6. 파일 구조

```
index.html              참가자 앱
board.html              실시간 현황판 (모니터용)
assets/
  config.js             Supabase URL · publishable key · 연수 목록
  data.js               실습지 A/B, 판단 기준, 5단계, 문장 틀 (원문 그대로)
  styles.css            참가자 화면 스타일 (원본 디자인 토큰 유지)
  app.js                참가자 + 관리자 로직
  board.css / board.js  현황판
supabase/
  schema.sql            테이블 · RLS · RPC · Realtime (한 번만 실행)
```
